# bftport

Консольный менеджер `kubectl port-forward` с мышью: запускайте и останавливайте проброс сервисов вживую, добавляйте новые, собирайте наборы (шаблоны) и запускайте их одним нажатием.

## Требования

- [Node.js](https://nodejs.org) 18 или новее
- `kubectl` в `PATH`
- Windows Terminal (на Windows) или любой терминал с поддержкой мыши

## Установка

```
npm install -g git+https://<gitlab-хост>/<группа>/bftport.git
```

Если репозиторий приватный, нужен доступ по SSH или токену, как для обычного `git clone`:

```
npm install -g git+ssh://git@<gitlab-хост>/<группа>/bftport.git
```

Обновление: `bftport --update` сравнит установленную версию с репозиторием и обновится, если есть новее (или сообщит, что версия актуальна). Нужен `git` с доступом к репозиторию. Удаление: `npm uninstall -g bftport`.

Проверка: `bftport --version`, `bftport --help` (покажет, куда установлено и где лежит база).

## Первый запуск

1. Выполните `bftport`.
2. Нажмите `K`: программа спросит папку, где лежат ваши kubeconfig-файлы, и покажет их список. Выберите нужный.
3. Стартовый набор сервисов уже в списке. Свои добавляйте клавишей `A`; кнопка «Выбрать из кластера» (`F2`) подтянет namespace, service и порты прямо из кластера.

### Логи пода (как в Lens)

`L` (или клик по заголовку «Логи» внизу) открывает выбранный сервис на весь экран. Это живой поток `kubectl logs -f` (в начале последние 300 строк). Работает и без запущенного проброса.

- Если у сервиса один под, его логи открываются сразу без префиксов, а имя пода и время его старта показаны в верхней полосе.
- Если подов несколько, сначала откроется список: имя, статус и время старта каждого пода. Есть и пункт «Все поды»: строки всех подов подряд, у каждой префикс с именем пода.
- `P` позволяет сменить под, не выходя из просмотра. Если выбранный под исчез (например, при выкатке), просмотр сам перейдёт на единственный новый под или предложит выбрать.

| Клавиша | Действие |
|---|---|
| `↑` `↓`, колесо, `PgUp` `PgDn`, `Home` | прокрутка; при прокрутке поток ставится на паузу (`⏸`), новые строки копятся |
| `End` | вернуться к концу, снова live |
| `/`, `Ctrl+F` | поиск (см. ниже); `Esc` закрывает |
| `F` | формат: JSON-логи приводятся к шаблону logback или показываются как есть |
| `W` | переносить длинные строки или обрезать |
| `P` | сменить под |
| `R` | перечитать с нуля; `C` — очистить окно |
| `Tab`, `1` `2` | источник: логи пода или вывод port-forward |
| `Esc`, `Q` | назад (поток останавливается) |

**Поиск** работает как в IntelliJ: в строке поиска вводится текст, все совпадения подсвечиваются (жёлтым), текущее ярче (оранжевым), рядом показывается номер совпадения и их количество (`3/12`). Регистр не важен.

| Клавиша в поиске | Действие |
|---|---|
| `↓`, `Enter`, `F3` | следующее совпадение (после последнего — снова первое) |
| `↑`, `Shift+F3` | предыдущее совпадение |
| `PgUp`, `PgDn`, колесо | обычная прокрутка |
| `Tab` | режим: «подсветка» (показан весь лог) или «фильтр» (только строки с совпадением) |
| `Esc` | закрыть поиск и убрать подсветку |

Прокрутка при переходах устроена так: вокруг центра окна есть «зона покоя» (60% высоты окна). Если следующее совпадение уже внутри неё, окно стоит на месте, просто передвигается яркая подсветка. Если совпадение снаружи или его не видно, лог прокручивается так, чтобы оно оказалось по центру. При вводе текста сначала выбирается ближайшее к центру совпадение ниже него, а если ниже совпадений нет, последнее.

**Формат.** Сервисы в кластере обычно пишут JSON. Просмотр разбирает такие строки и выводит их по шаблону logback, чтобы читать было так же, как локально:

```
2026-10-29 12:34:57.001 ERROR [main] [traceId = abc123] [spanId = def456] o.s.b.SpringApplication - Не удалось
```

Шаблон берётся из `<pattern>` файла `~/.m2/logback-local.xml`; если файла нет, используется встроенный, такой же. Поддерживаются поля logstash-logback-encoder, Spring Boot ECS и JSON-энкодера logback (время, уровень, поток, логгер, сообщение, `traceId`/`spanId` в корне или в `mdc`, стектрейс). Время показывается в вашем часовом поясе. Строки, которые не похожи на JSON-лог, выводятся без изменений. `F` переключает на исходный вид.

Строки с `ERROR`/`FATAL` красятся красным, `WARN` — жёлтым. Если поток оборвался (например, под перекатили), просмотр сам переподключается и подтягивает только то, что появилось за время обрыва. В окне хранятся последние 5000 строк.

### Настройки и язык

`O` (или кнопка «Настройки» внизу) открывает окно настроек:
- **Папка с kubeconfig**: та же папка, из которой `K` показывает список конфигов.
- **Язык / Language**: Русский или English. Переключается сразу, без перезапуска; выбор сохраняется. Если язык ещё не выбирали, берётся язык системы (русская локаль — русский, иначе английский).
- **О приложении**: версия.

Переводится интерфейс, справка (`bftport --help`) и сообщения в консоли. Ваши данные (имена сервисов и шаблонов, текст в полях ввода, строки логов) всегда показываются как есть. Английские тексты лежат в `i18n.js`.

### Несколько kubeconfig

Папка с конфигами задаётся один раз, дальше `K` (или клик по имени конфига в правом верхнем углу) открывает список файлов из неё, текущий отмечен `●`. Выбрали другой — и он становится общим для всех сервисов. Если в этот момент что-то запущено на прежнем конфиге, программа спросит подтверждение и остановит эти пробросы (они привязаны к кластеру). Сервисы со своим kubeconfig, заданным в форме, не затрагиваются.

## Где что лежит

| | Путь |
|---|---|
| Программа | `%APPDATA%\npm\node_modules\bftport` (Windows), `$(npm root -g)/bftport` (macOS/Linux) |
| Команда `bftport` | `%APPDATA%\npm\bftport.cmd`, она в `PATH` вместе с `npm` |
| Ваши данные | `~/.bftport/services.json` (сервисы, шаблоны, kubeconfig) |

Обновление программы базу не трогает. Базу можно переносить между компьютерами (сервисы, шаблоны, язык сохранятся), но пути к kubeconfig в ней абсолютные и привязаны к системе: при переносе с Windows на Linux (или наоборот) они сбрасываются, и программа предложит выбрать папку с конфигами заново (`O`). Чтобы сбросить всё к стартовому набору, удалите `~/.bftport/services.json`.

## Управление

| Клавиша | Действие |
|---|---|
| `↑` `↓`, колесо, клик | выбрать |
| `Enter`, `Пробел`, двойной клик | старт / стоп |
| `A` / `E` / `D` | добавить / изменить / удалить |
| `S` / `X` | запустить / остановить все видимые |
| `/`, `Ctrl+F` | поиск по имени, namespace, service, портам, статусу |
| `1` `2` `3` `4`, `Tab` | вкладки: Избранное, Запущенные, Шаблоны, Кластер |
| `L` | логи пода на весь экран (см. ниже) |
| `G` | сохранить запущенные сервисы как шаблон (на вкладке «Избранное») |
| `K` | выбрать kubeconfig из папки (`F2` в списке — сменить папку) |
| `O` | настройки: папка с kubeconfig, язык интерфейса, сведения о приложении |
| `Q` | выход (пробросы останавливаются) |

Горячие клавиши работают и в русской раскладке.

### Вкладка «Кластер» (4)

Показывает **все поды кластера** из выбранного kubeconfig, без ручного добавления сервисов (как в Lens). Список обновляется сам раз в несколько секунд, пока вкладка открыта.

| Клавиша | Действие |
|---|---|
| `/` | поиск по namespace, имени и статусу пода |
| `Enter`, двойной клик | если под относится к сервису из «Избранного» — запускает этот сервис на его порту (без формы), иначе открывает форму проброса порта пода; повторное нажатие останавливает |
| `P` | пробросить порт именно этого пода напрямую (форма: порт пода и свободный локальный) |
| `L` | логи пода (тот же просмотр; `P` в нём — выбор контейнера) |
| `F` | перенести в «Избранное»: приложение само найдёт Service этого пода и заполнит форму (имя, namespace, порт сервиса, свободный локальный порт) |
| `N` | показать один namespace (или «Все»); если нет прав на весь кластер — введите namespace вручную |
| `R` | обновить сразу |

Список запрашивается компактно (серверная таблица, как у обычного `kubectl get pods`), поэтому работает и на больших кластерах; подробности выбранного пода (контейнеры, порты) подгружаются отдельно. На очень больших кластерах обновление идёт реже: пауза растёт вместе со временем загрузки.

В списке видны READY, статус (`CrashLoopBackOff`, `Pending` и т. д. цветом), число перезапусков, возраст и активные пробросы; под списком — узел, IP, контейнеры и их порты. Пробросы к подам живут только в текущей сессии и в базу не записываются (имена подов эфемерны).

**Связь с «Избранным».** Приложение сопоставляет поды с избранными сервисами (по `selector` сервиса и меткам пода). Под такого сервиса помечен `★` в колонке «ПРОБРОС», а состояние сервиса (стоп / работает / ошибка) показывается и здесь, и в «Избранном», и в «Запущенных»: это один и тот же проброс. Учтите, что проброс через сервис идёт на любой из его подов, а не обязательно на выбранный; если нужен именно этот под, используйте `P`. Все активные пробросы, включая прямые пробросы к подам (они помечены `⎈`), видны на вкладке «2 Запущенные»; прямые пробросы там можно остановить (`Enter`), но не изменить и не удалить.

**Только просмотр.** Приложение вызывает `kubectl` только с командами `get`, `logs` и `port-forward`; любая другая (`delete`, `exec`, `edit`, `apply`, `scale`, `rollout` и т. п.) блокируется в коде. Поды, деплойменты и прочие объекты кластера через приложение изменить нельзя. Для списка нужны права `get`/`list` на поды, для логов — `pods/log`, для проброса — `pods/portforward`.

### Ввод текста

Во всех полях (формы, поиск, фильтры) работает редактирование с курсором: `←` `→`, `Home`/`End`, `Delete`, `Ctrl+←`/`Ctrl+→` (по словам), `Ctrl+W` (стереть слово назад), `Ctrl+U` (очистить поле). Вставка из буфера обмена: `Ctrl+V` или `Shift+Insert`. Если вставить текст, когда поиск не открыт, он откроется сам с вставленным запросом (удобно для UUID в логах). Многострочный текст склеивается в одну строку и не отправляет форму.

### Шаблоны

Шаблон — именованный набор сервисов (например `or-bpmn`). На вкладке «Шаблоны» `Enter` или двойной клик запускает весь набор, повторное нажатие останавливает его. Проще всего: запустите нужные сервисы, нажмите `G` и назовите шаблон.

## Если не работает мышь

Выполните `bftport --keys`, кликните в окне и пришлите вывод. Если при клике ничего не печатается, мышь не доходит до программы. Попробуйте Windows Terminal.
