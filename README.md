# bftport

**Терминальный менеджер `kubectl port-forward` и просмотрщик логов подов.** Один экран вместо россыпи терминалов: пробрасывайте порты сервисов и подов, держите наборы сервисов под рукой, ищите нужный под во всём кластере и читайте его логи прямо в консоли.

## Зачем это нужно

Обычный сценарий работы с кластером из терминала выглядит так: десяток вкладок с `kubectl port-forward …`, скрипт, который нужно править и перезапускать при каждом новом сервисе, и отдельный инструмент (Lens, Octant и т. п.), чтобы посмотреть, что вообще запущено и что пишет под в лог.

`bftport` собирает это в одно консольное приложение:

- **Пробросы управляются вживую.** Добавить сервис, остановить один из десяти, запустить целый набор («всё, что нужно для моего микросервиса») можно, не трогая файлы и не перезапуская остальное.
- **Кластер виден без ручной настройки.** Поды находятся сами; сервис, к которому они относятся, подбирается автоматически.
- **Логи читаются там же.** Живой поток, поиск с подсветкой, регулярные выражения, выделение и копирование мышью, экспорт в файл, раскладка JSON.
- **Ничего не ломается за вас.** Приложение умеет только читать из кластера и открывать порты (см. [Безопасность](#безопасность)).
- **Нет зависимостей.** Один пакет на Node.js без сторонних модулей и сборки.

## Возможности

### Пробросы портов

| Возможность | Подробности |
|---|---|
| Управление вживую | Запуск, остановка, добавление, правка и удаление сервисов без перезапуска приложения и без правки скриптов |
| Избранное | Сохранённые сервисы: namespace, service, локальный порт, порт сервиса (имя или номер), свой kubeconfig, автозапуск |
| Шаблоны | Именованные наборы сервисов, запуск и остановка одним нажатием; шаблон можно собрать из запущенного («сохранить запущенные как шаблон») |
| Самовосстановление | Упавший проброс (например, при перезапуске пода) перезапускается сам с растущей паузой: 2 с, 4 с, 6 с … до 15 с |
| Проверка порта | Занятый локальный порт обнаруживается до запуска и показывается как ошибка с понятной причиной |
| Автозапуск | Отмеченные сервисы стартуют вместе с приложением |
| Привилегированные порты | На Linux порт ниже 1024 (например, 80) пробрасывается через `sudo`, пароль запрашивается в приложении |
| Подбор параметров | Кнопка «Выбрать из кластера» подтягивает namespace, service и порты из кластера |

### Обзор кластера

| Возможность | Подробности |
|---|---|
| Все поды кластера | Вкладка «Кластер»: namespace, имя, READY, статус (цветом), перезапуски, возраст, узел, IP, контейнеры и порты |
| Большие кластеры | Список запрашивается серверной таблицей, а не полным JSON; проверено на эмуляции кластера в 30 000 подов |
| Живое обновление | Автообновление, пауза растёт вместе со временем загрузки, чтобы не нагружать API-сервер |
| Связь «под ↔ сервис» | По `selector` сервиса и меткам пода; под избранного сервиса помечен `★`, его состояние общее на всех вкладках |
| Проброс к поду | Напрямую к конкретному поду (`pod/…`), с подсказкой порта из спецификации пода и свободного локального порта |
| Перенос в избранное | Из пода одним нажатием: найдёт Service, заполнит форму (имя, namespace, порт, свободный локальный порт) |
| Фильтр по namespace | Один namespace или все; ручной ввод, если нет прав на весь кластер |

### Просмотр логов

| Возможность | Подробности |
|---|---|
| Живой поток | `kubectl logs -f`, в начале последние 300 строк, в окне хранится до 5000; автопереподключение с догрузкой пропущенного |
| Выбор пода и контейнера | Один под открывается сразу; если подов несколько, показывается список со временем старта; есть режим «все поды» с префиксами; sidecar-контейнеры (Istio и др.) по умолчанию пропускаются |
| Три вида | «Как есть», «logback» (JSON-записи по вашему шаблону), «logback + JSON» (объекты внутри сообщения раскладываются с отступами); переключение по кругу, позиция в логе сохраняется |
| Поиск как в IntelliJ | Подсветка всех совпадений, текущее ярче, счётчик `3/12`, переходы стрелками, `Enter`, `F3`; режим «фильтр» |
| Регулярные выражения | Переключатель `.*` (`Ctrl+R`), ошибки выражения показываются, пустые совпадения игнорируются |
| Выделение и копирование | Мышью: перетаскивание, двойной клик — слово (UUID, traceId), тройной — строка; `Ctrl+C` копирует в буфер ОС и через OSC 52 |
| Экспорт | «Видимые» (то, что на экране) или «все логи пода» (потоком в файл, без загрузки в память) |
| Цвет по уровню | `ERROR`/`FATAL` красным, `WARN` жёлтым, `DEBUG`/`TRACE` приглушённо |

### Интерфейс

| Возможность | Подробности |
|---|---|
| Боковая панель | Справа детали выбранного сервиса или пода (адрес, цель, kubeconfig, контейнеры и порты) и кнопки действий; на узких окнах (меньше 108 колонок) панель скрывается |
| Группы по namespace | Сервисы в «Избранном» и «Запущенных» собраны под заголовками namespace |
| Палитра команд | `Ctrl+P`: поиск по всем действиям текущей вкладки; дополняет клавиши, а не заменяет их |
| Два набора значков | Unicode (работает везде) и Nerd Font (Linux/macOS); выбирается в настройках |
| Мышь и клавиатура | Клики, двойной клик, колесо, перетаскивание; всё доступно и с клавиатуры, и в русской раскладке |
| Поиск на каждой вкладке | У каждой вкладки свой запрос; он сохраняется при переключении |
| Редактирование ввода | Курсор, слова, вставка из буфера (включая многострочный текст), маскированный ввод пароля |
| Два языка | Русский и English, переключение на лету; язык по умолчанию определяется по системе |
| Терминалы | Основной целевой терминал — Windows Terminal; рассчитано на любые терминалы со стандартными xterm-последовательностями (Linux, macOS, SSH); запасные способы копирования |
| Самообновление | `bftport --update` сравнивает версию с репозиторием и ставит новую |

## Требования

| Компонент | Требование |
|---|---|
| [Node.js](https://nodejs.org) | 18 или новее |
| `kubectl` | в `PATH`; рекомендуется 1.17 или новее (используются флаги `logs --prefix` и `--max-log-requests`) |
| `git` | только для `bftport --update` и установки из репозитория |
| Терминал | Рекомендуется Windows Terminal. Подойдёт любой современный терминал со стандартными VT/xterm-последовательностями и (желательно) мышью в режиме SGR; на других терминалах проверялось меньше |
| Права в кластере | `get`/`list` на поды и сервисы (и namespaces), `pods/log`, `pods/portforward`; больше ничего |

Для копирования в буфер обмена на Linux нужна одна из утилит `wl-copy`, `xclip`, `xsel` (без них остаётся OSC 52, см. [Платформы](#платформы-и-терминалы)).

## Установка и обновление

```bash
# установка из репозитория
npm install -g git+https://github.com/Norwi4/bftport.git

# для приватного репозитория через SSH
npm install -g git+ssh://git@<хост>/<группа>/bftport.git

# проверка
bftport --version
bftport --help          # покажет, куда установлено и где лежит база данных
```

**Обновление** одной командой: `bftport --update`. Команда делает неглубокий `git clone` репозитория из `package.json`, сравнивает версии и, если в репозитории новее, выполняет `npm install -g`. Если версия актуальна, сообщит об этом, если установленная новее репозитория, ничего не делает. Ваши данные (`~/.bftport`) обновление не затрагивает.

### Откат на версию 1.x

Последняя версия прежнего интерфейса — **1.4.4** (тег `v1.4.4`, ветка `legacy-1.x`). Вернуться на неё:

```bash
npm install -g git+https://github.com/Norwi4/bftport.git#v1.4.4
bftport --version      # bftport v1.4.4
```

Данные (`~/.bftport/services.json`) общие для обеих версий: сервисы и шаблоны остаются на месте. Версия 2.0 дописывает в файл поле `icons`, 1.4.4 его просто игнорирует.

**Важно:** не запускайте после отката `bftport --update` — он обновит приложение до последней версии из `main` (то есть снова до 2.x). Чтобы снова перейти на новый интерфейс, достаточно `bftport --update`. Версии 1.x выше 1.4.4 выпускаться не будут; все новые возможности и исправления идут в ветку 2.x.

**Удаление:** `npm uninstall -g bftport` (данные в `~/.bftport` остаются; удалите папку вручную, если не нужна).

**Куда ставится** (Windows / macOS и Linux):

| | Windows | macOS / Linux |
|---|---|---|
| Пакет | `%APPDATA%\npm\node_modules\bftport` | `$(npm root -g)/bftport` |
| Команда `bftport` | `%APPDATA%\npm\bftport.cmd` | `$(npm prefix -g)/bin/bftport` |
| Данные | `%USERPROFILE%\.bftport\services.json` | `~/.bftport/services.json` |

## Быстрый старт

1. Запустите `bftport` в обычном терминале.
2. Нажмите **`K`**: укажите папку, где лежат ваши kubeconfig-файлы, и выберите нужный (стрелки, `Enter`; можно набирать часть имени для фильтра).
3. Перейдите на вкладку **`4`** («Кластер»): подтянется список подов выбранного кластера. Найдите нужный (`/` для поиска).
4. Нажмите **`F`** («В избранное»): приложение найдёт Service этого пода и заполнит форму; подтвердите `Enter`. Сервис попадёт на вкладку «Избранное».
5. На вкладке **`1`** выберите сервис и нажмите **`Enter`**: порт проброшен. Повторный `Enter` останавливает.
6. **`L`** откроет логи пода; **`G`** сохранит запущенные сервисы как шаблон; **`O`** откроет настройки (язык и др.).

Справка по клавишам всегда под рукой: `bftport --help`.

## Основные понятия

| Понятие | Что это |
|---|---|
| **Сервис (избранное)** | Запись «что и куда пробросить»: `namespace/service`, локальный порт, порт сервиса, необязательный свой kubeconfig, автозапуск. Хранится в базе. Проброс идёт на `service/<имя>`, то есть переживает пересоздание подов |
| **Проброс** | Запущенный процесс `kubectl port-forward`. Состояния: `○` стоп, `◐` запуск, `●` работает, `↻` рестарт, `✖` ошибка |
| **Шаблон** | Именованный набор сервисов, запускается и останавливается целиком |
| **Kubeconfig** | Файл доступа к кластеру. Один «общий» выбирается клавишей `K` из папки с конфигами; у отдельного сервиса может быть свой |
| **Под** | Строка на вкладке «Кластер». Можно открыть его логи, пробросить порт напрямую к нему (`pod/<имя>`, только на время сессии) или перенести его сервис в избранное |
| **Вид логов** | Как показываются строки: «как есть», «logback», «logback + JSON» |

## Руководство

### Вкладка «Избранное» (1)

Список сохранённых сервисов с портами и статусом. Внизу журнал выбранного сервиса (вывод `kubectl port-forward`, последние 300 строк); `L` или клик по заголовку журнала открывает логи пода.

**Поля сервиса** (форма `A` / `E`):

| Поле | Описание |
|---|---|
| Имя | Как сервис называется в списке |
| Namespace, Service | Куда пробрасывать (`service/<Service>` в `<Namespace>`) |
| Локальный порт | Порт на вашей машине, 1–65535; уникален среди сохранённых сервисов |
| Порт сервиса | Имя порта (`grpc`, `http`) или номер |
| Kubeconfig | Пусто — общий; иначе путь к своему файлу |
| Автозапуск | Запускать вместе с приложением |

`F2` в форме открывает выбор из кластера (namespace → service → порт) и подставляет значения. Локальный порт по умолчанию равен порту сервиса.

**Проброс.** Команда, которую запускает приложение:

```text
kubectl -n <namespace> port-forward --address 0.0.0.0 service/<service> <локальный>:<порт сервиса> --kubeconfig=<файл>
```

Статус `работает` ставится, когда `kubectl` напечатал `Forwarding from …`. Если процесс завершился сам, проброс перезапускается: паузы 2, 4, 6 … 15 секунд (максимум). Остановка вручную отменяет перезапуск. Изменение запущенного сервиса перезапускает его с новыми параметрами.

### Вкладка «Запущенные» (2)

Всё, что запущено сейчас: сохранённые сервисы и прямые пробросы к подам (помечены `⎈`). Те же `Enter`, `L`, `S`, `X`. Прямые пробросы к подам здесь можно остановить, но не изменить и не удалить (они живут только в этой сессии). Число в заголовке вкладки — количество запущенных.

### Вкладка «Шаблоны» (3)

Шаблон — набор сервисов. `Enter` или двойной клик запускает все его сервисы, которые ещё не запущены; если запущены все, останавливает весь набор. В нижней панели видны состав и статусы участников. Создать: `A` (форма: название + выбор сервисов, `F2`), либо собрать из запущенного клавишей `G` на вкладке «Избранное». Удаление шаблона не удаляет сами сервисы; при удалении сервиса он исчезает и из шаблонов.

### Вкладка «Кластер» (4)

Обзор подов кластера выбранного kubeconfig. **Только просмотр:** изменить поды, деплойменты и любые объекты через приложение нельзя.

| Колонка | Смысл |
|---|---|
| NAMESPACE / ИМЯ | Namespace и имя пода |
| READY | Готовые контейнеры из общего числа |
| СТАТУС | Статус как у `kubectl get pods` (`Running`, `CrashLoopBackOff`, `Pending` …), цветом |
| РЕСТ / ВОЗРАСТ | Число перезапусков и возраст |
| ПРОБРОС | `⇄ :порт` — прямой проброс к этому поду; `★ имя :порт` — состояние избранного сервиса, к которому относится под |

Под списком — узел, IP, время создания, число перезапусков, контейнеры и их порты.

**Действия:**

| Клавиша | Действие |
|---|---|
| `Enter` | Если под принадлежит сервису из «Избранного» — запускает/останавливает этот сервис на его порту (без формы). Иначе открывает форму проброса порта пода |
| `P` | Проброс именно к этому поду: форма с портом пода (из спецификации) и свободным локальным портом |
| `L` | Логи пода |
| `F` | Перенести в «Избранное»: находит Service по selector, при нескольких предлагает выбор, подставляет имя, namespace, порт и свободный локальный порт |
| `N` | Показать один namespace (или все); если на весь кластер нет прав, введите namespace вручную |
| `R` | Обновить сейчас |

**Связь с избранным.** Под считается принадлежащим сервису, если `selector` сервиса целиком входит в метки пода. Учтите: проброс через сервис идёт на любой из его подов, не обязательно на выбранный; если нужен именно этот под, используйте `P`.

**Обновление.** Пока вкладка открыта (и не открыты поиск или форма), список обновляется в фоне; следующее обновление не раньше чем через `max(8 с, 8 × время предыдущей загрузки)`. Детали выбранного пода запрашиваются отдельно (с кэшем на 30 секунд), соответствие сервисам обновляется раз в минуту.

### Просмотр логов

Открывается `L` на вкладках «Избранное», «Запущенные» и «Кластер» на весь экран. Это живой `kubectl logs -f`, работает и без запущенного проброса.

**Выбор пода.** Один под: открывается сразу, имя и время старта в верхней полосе. Несколько подов: сначала список с именем, статусом и временем старта плюс пункт «Все поды» (строки всех подов подряд с префиксом). `P` в просмотре меняет под (или контейнер, если открыт под из вкладки «Кластер»). Если выбранный под исчез при выкатке, просмотр сам перейдёт на единственный новый под или предложит выбрать.

**Поток.** В начале загружаются последние 300 строк; в окне хранится до 5000. Если поток оборвался, просмотр переподключается (паузы 3, 6 … 15 с) и берёт только то, что появилось за время обрыва (`--since`). Прокрутка вверх ставит просмотр на паузу (`⏸`), `End` возвращает в «живой» режим.

#### Три вида (клавиша `F` по кругу)

| Вид | Что показывает |
|---|---|
| Как есть | Строки в исходном виде |
| logback | JSON-записи лога приводятся к шаблону logback; строки не в JSON не меняются |
| logback + JSON | То же, плюс объекты и массивы JSON внутри сообщения раскладываются с отступами |

При смене вида окно остаётся на том же месте лога (запоминается запись вверху окна); если вы читали «живой» хвост, остаётесь внизу.

**Вид logback.** Шаблон берётся из `<pattern>` файла `~/.m2/logback-local.xml`; если файла нет, используется встроенный:

```text
%d{yyyy-MM-dd HH:mm:ss.SSS} %-5level [%thread] [traceId = %X{traceId}] [spanId = %X{spanId}] %logger{36} - %message%n%rEx
```

Поддерживаются поля logstash-logback-encoder, Spring Boot ECS и JSON-энкодера logback: время, уровень, поток, логгер, сообщение, `traceId`/`spanId` в корне или в `mdc`, стектрейс. Время показывается в вашем часовом поясе.

**Вид «logback + JSON».** Пример: строка

```text
… - Начато выполнение метода Foo/Bar c параметрами {"id":{"value_":1},"items":[{"sku":"A"}]}. Вызвал: svc
```

превращается в блок

```text
… - Начато выполнение метода Foo/Bar c параметрами {
  "id": {
    "value_": 1
  },
  "items": [
    {
      "sku": "A"
    }
  ]
}. Вызвал: svc
```

Правила: JSON ищется в обычных строках и в сообщении JSON-записей; текст до и после объекта остаётся на своих местах; цвет блока задаёт уровень строки. Отступы расставляются по исходному тексту, поэтому числа (в том числе очень большие), порядок ключей и содержимое строк не меняются. Не трогаются мелочи (`[1, 2, 3]`, `{}`), невалидный JSON, обычные скобки (`[main]`, `Foo[bar=1]`) и слишком большие объекты (больше 500 строк после раскладки).

#### Поиск

`/` или `Ctrl+F` открывает строку поиска. Регистр не важен.

| Клавиша | Действие |
|---|---|
| ввод текста | Подсвечиваются все совпадения (жёлтым), текущее ярче (оранжевым), показывается `N/M` |
| `↓`, `Enter`, `F3` | Следующее совпадение (после последнего снова первое) |
| `↑`, `Shift+F3` | Предыдущее |
| `Tab` | Режим: «подсветка» (виден весь лог) или «фильтр» (только строки с совпадением) |
| `Ctrl+R` или клик по `.*` | Регулярные выражения (синтаксис JavaScript, флаги `gi`) |
| `PgUp`, `PgDn`, колесо | Обычная прокрутка |
| `Ctrl+S` | Экспорт из открытой строки поиска |
| `Esc` | Закрыть поиск и убрать подсветку |

**Прокрутка к совпадению.** Вокруг центра окна есть «зона покоя» (60% высоты). Если следующее совпадение уже внутри неё, окно стоит на месте, перескакивает только яркая подсветка; если снаружи или не видно, лог прокручивается так, чтобы совпадение оказалось по центру. При вводе выбирается ближайшее к центру совпадение ниже него, а если ниже нет, последнее.

Вставка текста, когда поиск закрыт, сама открывает его с вставленным запросом (удобно для UUID).

#### Выделение и копирование

Протяните мышью по тексту (у верхнего и нижнего края окна лог подкручивается сам). Двойной клик выделяет слово (до пробела, скобок, кавычек, запятых — так целиком берутся UUID, traceId, пути), тройной всю строку. `Ctrl+C` или `Ctrl+Insert` копирует и снимает выделение, `Esc` или одиночный клик снимают без копирования. Без выделения `Ctrl+C` закрывает просмотр.

Выделение привязано к тексту, а не к экрану: оно не «уезжает» при прокрутке и притоке новых строк. Строка, перенесённая на несколько экранных, копируется целиком и без лишних переводов строки. Смена вида снимает выделение.

#### Экспорт в файл

`E` (при открытом поиске `Ctrl+S`). Доступен только для логов одного пода (не для вывода port-forward и не в режиме «все поды»).

| Вариант | Что попадает в файл |
|---|---|
| **Видимые** | Строки, помещающиеся на экране в момент нажатия: с учётом вида, прокрутки и фильтра. Строка, у которой видна хотя бы часть, попадает целиком. Подсветка не сохраняется |
| **Все логи пода** | Весь `kubectl logs` пода без ограничения по числу строк; пишется потоком прямо в файл (не копится в памяти), в том же виде, что в окне |

Путь по умолчанию: `~/bftport-logs/<под>_<ГГГГММДД-ЧЧММСС>.log` (`_all` для полного лога). Папка создаётся сама, существующие файлы не перезаписываются. Если закрыть просмотр во время экспорта, он прерывается, а недокачанный файл удаляется.

### Kubeconfig

В настройках (или по `F2` в списке конфигов) задаётся **папка** с kubeconfig-файлами. `K` (или клик по имени конфига в правом верхнем углу) показывает файлы из неё; выбранный становится общим для всех сервисов и вкладки «Кластер». Если в этот момент что-то запущено через общий конфиг, приложение спросит подтверждение и остановит эти пробросы (они привязаны к кластеру). Сервисы со своим kubeconfig в форме не затрагиваются.

### Настройки и язык

`O` (или кнопка «Настройки») открывает окно: папка с kubeconfig, **язык** (Русский / English, применяется сразу), **значки** (авто / Unicode / Nerd Font / ASCII), переключатель **«Открывать логи в отдельном окне»**, сведения о приложении (версия). Если язык не выбран, берётся язык системы (русская локаль → русский, иначе английский). Переводятся интерфейс, справка и сообщения в консоли; пользовательские данные (имена, текст в полях, строки логов) не переводятся никогда.

**Отдельное окно логов.** Если переключатель включён, `L` открывает второй процесс `bftport` в новом окне терминала. Он показывает тот же просмотрщик логов, но не запускает автозапуск сервисов и не управляет пробросами основного окна. На Windows работает при запуске из cmd и PowerShell; для создания нового окна используется PowerShell. На Debian с графическим окружением используется системный `x-terminal-emulator`, на ALT Linux — Konsole. Терминал определяется автоматически по системе, пользователю не нужно задавать флаги. Если отдельное окно недоступно, логи открываются в текущем терминале. На остальных системах пока используется текущий терминал.

**Значки.** «Авто» выбирает Unicode на Windows и Nerd Font на Linux/macOS. Если в терминале не установлен Nerd Font, вместо значков будут пустые квадратики: выберите Unicode (или поставьте шрифт, например JetBrainsMono Nerd Font). Для одного запуска набор можно задать переменной окружения: `BFTPORT_ICONS=unicode bftport` (значения `unicode`, `nerd`, `ascii`).

**Палитра команд.** `Ctrl+P` на любой вкладке открывает список действий этой вкладки с поиском по названию; справа указана «родная» клавиша действия. Выбор выполняет то же, что и клавиша.

### Работа с текстовыми полями

Во всех полях (формы, поиск, фильтры): `←` `→`, `Home`/`End`, `Delete`, `Ctrl+←/→` (по словам), `Ctrl+W` (слово назад), `Ctrl+U` (очистить), вставка `Ctrl+V` или `Shift+Insert`. Многострочный текст склеивается в одну строку и не отправляет форму. Пароль `sudo` вводится маскированно.

## Справочник по клавишам и мыши

Буквенные клавиши работают и в русской раскладке (физическая клавиша, а не символ).

### Списки (вкладки 1–4)

| Клавиша | Действие |
|---|---|
| `↑` `↓`, `PgUp` `PgDn`, `Home` `End`, колесо | Перемещение выбора |
| `Enter`, `Пробел`, двойной клик | Запуск/остановка (на «Шаблонах» — набора, на «Кластере» — по правилам вкладки) |
| `1` `2` `3` `4`, `Tab`, клик по вкладке | Переключение вкладок |
| `/`, `Ctrl+F`, клик по полю | Поиск; `Esc` очищает запрос текущей вкладки |
| `A` / `E` / `D` или `Del` | Добавить / изменить / удалить (сервис или шаблон) |
| `S` / `X` | Запустить / остановить все видимые (на «Шаблонах» — выбранный шаблон) |
| `G` | Сохранить запущенные сервисы как шаблон (вкладка «Избранное») |
| `L` | Логи пода |
| `K` / `O` | Выбор kubeconfig / настройки |
| `Ctrl+P` | Палитра команд: поиск по действиям вкладки |
| `Q`, `Ctrl+C` | Выход (если есть пробросы, спросит подтверждение) |

Вкладка «Кластер»: `Enter`, `P`, `L`, `F`, `N`, `R` — см. [выше](#вкладка-кластер-4).

### Формы и выбор из списка

| Клавиша | Действие |
|---|---|
| `Tab`, `↓` / `Shift+Tab`, `↑` | Следующее / предыдущее поле |
| `Enter` | Сохранить / выполнить |
| `F2` | Дополнительное действие формы (выбор из кластера, выбор сервисов шаблона, выбор порта) |
| `Пробел`, `←` `→` | Галочка / переключатель (например, язык) |
| `Esc` | Отмена |
| В списках выбора: набор текста | Фильтр; `Пробел` отмечает пункт в многовыборе |

### Просмотр логов

| Клавиша | Действие |
|---|---|
| `↑` `↓`, `PgUp` `PgDn`, `Home`, колесо | Прокрутка (с активным поиском `↑↓` ходят по совпадениям) |
| `End` | К концу, снова «живой» режим |
| `/`, `Ctrl+F` | Поиск (внутри: `Enter`/`↓`/`F3` дальше, `↑`/`Shift+F3` назад, `Tab` подсветка/фильтр, `Ctrl+R` regex, `Ctrl+S` экспорт, `Esc` закрыть) |
| `F` | Вид по кругу: как есть → logback → logback + JSON |
| `W` | Перенос длинных строк / обрезка |
| `P` | Сменить под (контейнер) |
| `R` / `C` | Перечитать с нуля / очистить окно |
| `E` | Экспорт |
| `Tab`, `1` `2` | Источник: логи пода / вывод port-forward |
| Мышь | Выделение; двойной клик — слово; тройной — строка |
| `Ctrl+C`, `Ctrl+Insert` | Копировать выделенное (без выделения `Ctrl+C` закрывает просмотр) |
| `Esc`, `Q` | Снять выделение / закрыть поиск / выйти из просмотра |

### Диалоги подтверждения

`Y` или `Enter` — да, `N` или `Esc` — нет.

## Данные и конфигурация

Приложение хранит всё в одном JSON-файле. Переменные окружения для настройки не требуются.

| Что | Где |
|---|---|
| База | `~/.bftport/services.json` |
| Стартовый набор | `seed.json` внутри пакета; копируется в базу при первом запуске, если базы нет |
| Экспорт логов | `~/bftport-logs/` (по умолчанию) |
| Шаблон logback | `~/.m2/logback-local.xml` (необязательно) |

**Схема `services.json`:**

```json
{
  "lang": "ru",
  "icons": "auto",
  "logsWindow": false,
  "kubeconfig": "/home/me/kube/staging.yaml",
  "kubeconfigDir": "/home/me/kube",
  "services": [
    {
      "id": "a1b2c3d4",
      "name": "orders-api",
      "namespace": "shop",
      "service": "orders-api",
      "localPort": 8080,
      "remotePort": "http",
      "kubeconfig": "",
      "autostart": false
    }
  ],
  "groups": [
    { "id": "g1", "name": "checkout-flow", "services": ["a1b2c3d4"] }
  ]
}
```

| Поле | Описание |
|---|---|
| `lang` | `ru` или `en`; если нет, определяется по системе |
| `icons` | `auto`, `unicode`, `nerd` или `ascii` (с версии 2.0); если нет, `auto` |
| `logsWindow` | Открывать просмотрщик логов в отдельном терминале; по умолчанию `false` |
| `kubeconfig` | Общий kubeconfig (путь к файлу) |
| `kubeconfigDir` | Папка с конфигами; если не задана, выводится из `kubeconfig` |
| `services[].id` | Идентификатор (генерируется, если нет); на него ссылаются шаблоны |
| `services[].remotePort` | Имя порта или номер |
| `services[].kubeconfig` | Свой kubeconfig сервиса (пусто — общий) |
| `groups[].services` | Список `id` сервисов; несуществующие `id` отбрасываются при загрузке |

Запись атомарная (во временный файл и переименование). Файл можно править вручную, пока приложение закрыто. Чтобы сбросить всё к стартовому набору, удалите файл.

## Платформы и терминалы

| Платформа | Особенности |
|---|---|
| **Windows** | Лучше всего Windows Terminal. Консоль Windows по умолчанию перехватывает мышь (режим выделения QuickEdit), поэтому при старте приложение один раз выставляет режим консоли через PowerShell (вкл. передачу мыши, выкл. QuickEdit). Буфер обмена — PowerShell |
| **Linux** | Порты ниже `ip_unprivileged_port_start` (обычно 1024) требуют root: приложение запускает `kubectl` через `sudo -S`, пароль спрашивает само. Буфер обмена: `wl-copy`, `xclip`, `xsel` (по очереди) и OSC 52 |
| **Значки** | Windows: по умолчанию Unicode, работает в Windows Terminal и conhost. Linux/macOS: по умолчанию Nerd Font; без него выберите Unicode в настройках |
| **macOS** | Привилегированные порты на адресе `0.0.0.0` не требуют `sudo` (начиная с macOS Mojave); буфер обмена — `pbcopy` |
| **SSH / tmux** | Копирование работает через OSC 52, если терминал (и tmux с `set-clipboard on`) его пропускает |

**Мышь.** Приложение включает режимы терминала: основной экран заменяется альтернативным (`?1049`), отслеживание кликов и перетаскивания (`?1000`, `?1002`, `?1006`), «вставка в скобках» (`?2004`); при выходе всё возвращается. Родное выделение терминала при включённой мыши доступно с зажатым `Shift`. Если мышь не реагирует, выполните `bftport --keys` и кликните: если ничего не печатается, терминал не передаёт мышь программе.

### Привилегированные порты на Linux

Если локальный порт сервиса меньше порога, а приложение запущено не от root, при запуске появляется окно «Пароль sudo». Выполняется:

```text
sudo -S -p '' env HOME=<ваш HOME> PATH=<ваш PATH> kubectl <те же аргументы>
```

`HOME` и `PATH` передаются, чтобы `kubectl` под root нашёл ваши плагины авторизации и настройки. Пароль хранится только в памяти процесса до выхода, переиспользуется для следующих привилегированных пробросов (и автоперезапуска), не пишется ни в базу, ни в журналы. Неверный пароль даёт ошибку и повторный запрос; `Esc` отменяет запуск.

## Безопасность

### Только чтение

Все вызовы `kubectl` проходят проверку `assertReadOnly`: разрешены только глаголы

| Глагол | Для чего |
|---|---|
| `get` | список подов, сервисов, namespaces; данные пода |
| `logs` | чтение логов |
| `port-forward` | открытие локального порта |

Любой другой (`delete`, `exec`, `edit`, `apply`, `patch`, `scale`, `rollout`, `config` и т. д.) блокируется в коде до запуска процесса, независимо от того, откуда пришёл вызов. Приложение не изменяет объекты кластера и ваш kubeconfig.

### Что нужно знать

| Тема | Пояснение |
|---|---|
| Адрес проброса | Порты открываются на `0.0.0.0`, то есть доступны не только с вашей машины, но и по сети (так работал исходный скрипт, это нужно для обращения из контейнеров и VM). Если сеть недоверенная, используйте фаервол |
| Пароль sudo | Только в памяти процесса; в `services.json`, в журнале вызовов и в логах его нет; в интерфейсе вводится маскированно |
| Сеть и телеметрия | Приложение само не делает сетевых запросов. Сеть используют только `kubectl` (к вашему кластеру) и `git`/`npm` при `--update` |
| Зависимости | Нет сторонних runtime-зависимостей: меньше поверхности для атаки на цепочку поставки |
| Права | Нужны только права на чтение подов/сервисов/логов и проброс портов |
| Данные на диске | Только `services.json` (имена, namespace, порты, пути к kubeconfig) и файлы экспорта, которые вы сами запросили. Содержимое kubeconfig приложение не читает и не копирует: путь передаётся `kubectl` |

## Архитектура

Один процесс Node.js без зависимостей. Состояние хранится в памяти; на диск пишется только база.

```text
┌──────────────────────────── bftport (один процесс Node.js) ────────────────────────────┐
│                                                                                        │
│  Терминал ── ввод ──► разбор (клавиши, SGR-мышь, bracketed paste) ──► обработчик режима │
│      ▲                                                  (список, форма, выбор, логи)   │
│      └── кадр целиком (ANSI) ◄── отрисовка ◄── состояние UI (вкладки, поиск, просмотр) │
│                                                                                        │
│  База ~/.bftport/services.json ◄──► менеджер пробросов ─ spawn ─► kubectl port-forward │
│                                      клиент кластера ─── execFile ► kubectl get …      │
│                                      просмотр логов ──── spawn ───► kubectl logs -f …  │
│                                                                                        │
│  Все вызовы kubectl ──► assertReadOnly (get | logs | port-forward) ──► процесс          │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

**Устройство кода** (`bftport.js`, около 2500 строк, плюс `i18n.js`):

| Часть | Что делает |
|---|---|
| База | загрузка и атомарная запись JSON, выдача `id`, очистка ссылок шаблонов |
| Процессы | `start`/`stop`/`launch`: проверка порта, запуск `kubectl`, разбор вывода, перезапуск с паузой, учёт статусов |
| Клиент кластера | `kubeText`/`kube`: единая точка запросов, проверка read-only, лимиты времени и размера ответа |
| Отрисовка | собирает кадр из строк с разметкой, регистрирует «горячие зоны» для мыши; перерисовка объединяется (не чаще одного кадра за тик) |
| Ввод | разбор последовательностей терминала, режимы (список/форма/выбор/логи/подтверждение), общий редактор строки |
| Вкладки | избранное, запущенные, шаблоны, кластер; у каждой своё состояние поиска и выбора |
| Просмотр логов | поток, буфер, виды (`formatEntries`), поиск и regex, выделение, экспорт |
| i18n | перевод в момент отрисовки; исходные строки русские |

**Ключевые решения:**

- **Перевод на лету.** Тексты в коде русские; при выборе English строки переводятся из словаря (`i18n.js`) в момент вывода (сначала правила с подстановкой чисел, затем фразы по длине). Поэтому язык меняется без перезапуска. Пользовательские данные помечаются невидимыми маркерами и в перевод не попадают.
- **Выделение в логах привязано к тексту**, а не к экранным координатам: хранится «запись + позиция в ней». Поэтому оно переживает прокрутку, перенос строк и приток новых данных.
- **Позиция при смене вида.** Запоминается запись вверху окна и строка внутри неё; после пересчёта вида окно возвращается к ней.
- **Список подов через серверную таблицу** (`get pods -o wide --show-labels`): размер ответа в десятки раз меньше полного JSON. Подробности пода и связь с сервисами запрашиваются отдельно и кэшируются.
- **Экспорт полного лога потоком** с учётом обратного давления (`drain`), чтобы большой лог не занимал память.
- **Защита по умолчанию:** единая функция проверки аргументов `kubectl` для всех вызовов.

| Параметр | Значение |
|---|---|

## Диагностика и FAQ

| Симптом | Причина и решение |
|---|---|
| Вместо значков пустые квадратики | Нет Nerd Font: `O` → «Значки» → Unicode (или `BFTPORT_ICONS=unicode`) |
| Странные цвета | Интерфейс использует 24-битный цвет (truecolor): Windows Terminal, iTerm2, GNOME Terminal, kitty, Alacritty и др. поддерживают; в очень старых терминалах цвета будут приблизительными |
| Мышь не реагирует | Запустите `bftport --keys` и кликните. Если ничего не печатается, терминал не передаёт мышь; на Windows используйте Windows Terminal. Выделить текст самим терминалом можно с зажатым `Shift` |
| `Q` не выходит | Есть запущенные пробросы, показано подтверждение: нажмите `Y` (выйти и остановить) или `N` |
| Порт «занят» | Локальный порт уже слушает другой процесс. Освободите его или смените порт сервиса. На Linux для портов ниже 1024 потребуется `sudo` (приложение спросит пароль) |
| `kubectl не найден в PATH` | Установите `kubectl` или добавьте его в `PATH` |
| Список подов не загружается | Ответ показан в нижней части вкладки «Кластер». Типичные причины: нет kubeconfig (`K`), нет прав на весь кластер (нажмите `N` и выберите namespace), недоступен кластер. `R` повторяет запрос |
| `Forbidden` в логах/списках | Не хватает прав RBAC: нужны `get`/`list` на поды и сервисы, `pods/log`, `pods/portforward` |
| Проброс «рестарт» по кругу | Под или сервис недоступны, либо порт сервиса указан неверно; причина в журнале внизу вкладки «Избранное» и в колонке статуса |
| Копирование в Linux не работает | Установите `wl-copy`, `xclip` или `xsel`; без них текст уходит только через OSC 52, и терминал должен его поддерживать (в строке состояния будет сказано) |
| Пароль `sudo` не принимается | Проверьте пароль; при `requiretty` в sudoers приложение покажет отказ `sudo` в статусе сервиса |
| После переноса базы с Windows на Linux (или обратно) конфиги «не находятся» | Пути в базе абсолютные и привязаны к системе. Нажмите `O`, укажите папку с конфигами заново и выберите файл через `K` (при необходимости удалите поля `kubeconfig` и `kubeconfigDir` из `services.json`) |
| Данные пропали после аварии | Если `services.json` повреждён, приложение стартует с пустой базой и перезапишет файл при следующем сохранении. Делайте резервную копию `~/.bftport` |
| Как сменить язык | `O` → «Язык» |
| Где мои данные | `bftport --help` показывает путь к базе |

## Известные ограничения

- Пути в `services.json` абсолютные и не пересчитываются между системами (см. выше).
- Повреждённый `services.json` молча заменяется пустой базой в памяти (до следующего сохранения файл не перезаписывается).
- Выбор контекста внутри kubeconfig (`--context`) не поддерживается: используется `current-context` файла. Для разных кластеров держите разные файлы.
- Раскладка JSON работает по одной строке лога; JSON, разбитый на несколько строк, не склеивается.
- Поиск и фильтр действуют по тем строкам, которые есть в окне (до 5000), а не по всему логу пода; для полного лога используйте экспорт «все логи».
- Проброс через сервис выбирает под средствами `kubectl`, а не вы; для конкретного пода используйте прямой проброс.
- Тема тёмная; светлых тем терминала версия 2.0 пока не учитывает.
- Набор значков Nerd Font проверен на имитации терминала; на реальных шрифтах и терминалах (Linux, macOS) он отдельно не проверялся.
- Автотестов в репозитории пока нет (см. [Разработка](#разработка)).

## Разработка

**Запуск из исходников:**

```bash
git clone https://github.com/Norwi4/bftport.git
cd bftport
node bftport.js          # интерфейс
node --check bftport.js  # проверка синтаксиса
```

**Структура репозитория:**

| Файл | Назначение |
|---|---|
| `bftport.js` | Всё приложение (точка входа, `bin`) |
| `i18n.js` | Английские тексты и правила перевода, английская справка |
| `seed.json` | Стартовый набор сервисов и шаблонов |
| `package.json` | Метаданные, `bin`, список публикуемых файлов (`files`) |
| `README.md`, `CHANGELOG.md` | Документация и история версий |

**Соглашения:**

- Тексты интерфейса в коде русские; английский вариант добавляется в `i18n.js` (фразы и правила). Данные пользователя, смешанные с текстом, оборачиваются в `D(...)`, чтобы перевод их не трогал.
- Новые вызовы `kubectl` идут через `kube`/`kubeText`/`kspawn`, которые проверяют read-only; прямой `spawn('kubectl')` не использовать.
- Тяжёлые операции не должны блокировать отрисовку: сеть и файлы асинхронные, перерисовка идёт через `draw()`.
- Окончания строк LF (см. `.gitattributes`).

**Проверка без кластера.** Программа запускает `kubectl` из `PATH`, поэтому для проверки интерфейса достаточно положить впереди свой скрипт `kubectl`, который отвечает на `get pods`, `get svc`, `logs` и `port-forward` тестовыми данными. Автотестов в репозитории пока нет; их стоит добавить для разборщиков (раскладка JSON, шаблон logback, перевод), отрисовки и защиты read-only.

**Ветки и теги.** `main` — текущая линия 2.x. `legacy-1.x` и тег `v1.4.4` — зафиксированная последняя версия 1.x (только для отката, без дальнейших изменений).

**Выпуск версии.** Поднимите `version` в `package.json` (SemVer), добавьте запись в `CHANGELOG.md`, закоммитьте и отправьте в `main`. Пользователи получат версию командой `bftport --update` (сравнение идёт по номеру версии, поэтому без повышения номера обновление «не увидит» изменений).
